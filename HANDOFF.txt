2. CONTRAINTES D'ARCHITECTURE NON NÉGOCIABLES
════════════════════════════════════════════════════════════════════
- La RLS PostgreSQL est la SEULE frontière d'autorisation. JAMAIS de
  "WHERE company_id = ..." comme substitut dans le code applicatif.
  lib/rag/retrieveAuthorizedChunks.ts ne filtre volontairement pas en
  TypeScript (le filtrage est dans la requête SQL elle-même, via RLS)
  et contient une garde fail-loud : si une ligne d'une autre société
  apparaît malgré tout, une exception est levée plutôt qu'un filtrage
  silencieux. NE JAMAIS "corriger" ou retirer cette garde.

- Citations survivantes : la table citations stocke document_version_id
  + snippet_text + source_index EN DUR au moment de la réponse
  (lib/conversation/persist.ts). Une citation doit rester consultable
  même si le document/la version cités changent de statut ensuite
  (archivé, supprimé). Préserver ce mécanisme.

- Fail-closed : un utilisateur authentifié sans company_id ne doit
  JAMAIS avoir d'accès — lib/permissions/authContext.ts retourne null
  dans ce cas, traité comme un refus (401) partout, jamais de fallback
  ouvert ni de société par défaut.

- UI : icônes lucide-react UNIQUEMENT (zéro emoji — vérifié à l'instant,
  0 occurrence dans tout app/), nombres affichés via
  .toLocaleString('fr-FR') ou Intl.NumberFormat('fr-FR'), textes
  visibles "in-world" (jamais de méta-commentaire développeur type
  "pour tester W3" dans une description visible utilisateur).

- Migrations numérotées idempotentes dans db/migrations/. Prochain
  numéro disponible : 0019 (0018 est la dernière, déjà committée).

- Commits conventionnels feat:/fix:/ci:/docs:, un lot logique = un
  commit.

- app_role côté application (RLS-enforced, NOBYPASSRLS), JAMAIS le
  rôle postgres/superuser au runtime. migration_role/postgres réservé
  aux migrations/seed/maintenance (scripts db/*.mjs, scripts/*.mjs).

8. SCÉNARIO DE DÉMO VALIDÉ (pour la vidéo, 5 étapes, ~5 min)
════════════════════════════════════════════════════════════════════
1. Login admin ZEN Retail Tunisia → question RH → réponse avec
   citation cliquable → clic → page preview avec passage surligné.
2. Déconnexion, reconnexion admin ZEN Home & Lifestyle → même
   question (ou similaire) → sources différentes → preuve
   d'isolation cross-société.
3. Login employé ZEN Retail → demander la grille salariale
   (document restricted) → refus → preuve du filtrage par rôle,
   pas seulement par société.
4. Page admin → montrer coût estimé, feedback (👍/👎 réels via
   icônes lucide), pagination de l'activité.
5. Bibliothèque documents → badge "Révision dépassée" → mentionner
   le workflow W3 (scan/notification/dépublication automatique).

INTERDITS EN LIVE PENDANT L'ENREGISTREMENT :
  - Upload d'un PDF non testé au préalable (le chemin PDF dépend de
    dépendances natives — a déjà causé des bugs de production sérieux
    dans ce projet).
  - Suppression d'un document sans avoir un document de rechange
    préparé pour la suite de la démo.
  - Démonstration sur mobile/écran réduit tant que la passe
    responsive (P0 ci-dessus) n'est pas faite et vérifiée visuellement.
  - Premier appel sans "chauffe" — un cold start Vercel/embedding
